阶段摘要

本阶段关键决策

  • 一个纯产品 HTML 自然连通 GI-01 至 GI-06；家长设置、摄像头练习、键盘热身和两类输入结论均由真实产品操作到达
  • 键盘路径可真实试玩；摄像头权限拒绝有明确键盘恢复，家长确认切换会停止视频轨道
  • camera_full 与 keyboard_full 都交付三类标准动作，且 input-ready 对每次档案只派发一次

被放弃的方案

  • 不加入 prototype shell、inspector、screen-nav、state-nav 或调试按钮
  • 不在手势输入模块中伪造横版关卡，不引入账号、榜单、生命值或 Game Over
  • 不使用 Bluey 角色或官方资产；本原型只使用原创 SVG 小狗

进入下一阶段的条件

  • PM 确认 6 屏自然主干与低龄单动作舞台
  • PM 确认 InputProfile 交接、安全降级和摄像头轨道释放
  • PM 接受演示识别仅用于流程验证，真实儿童手势准确率仍待实现和验证

不需要 PM 审查的执行细节

  • SVG 路径、CSS 动画参数、fake media 参数和自动化选择器
  • 通用静态检查器要求 shell/inspector 的失败项；已确认规格明确禁止把脚手架放进纯产品画布

风险与下一步

风险

  • 演示识别按固定节奏产生成功事件，只验证状态机和体验节奏，绝不能据此宣称真实手势准确率
  • camera_hybrid 尚未进入 04B 主干；其产品规则已在 Phase 3/4A 确认，最终 MVP 接入真实识别时必须实现
  • 单文件直接以 file:// 打开时，不同浏览器可能限制摄像头；正式试玩应通过本地 HTTP 启动
  • 通用 prototype checker 仍报告 shell/inspector 缺失；这是与纯产品 04B 规则冲突的非阻塞检查项
