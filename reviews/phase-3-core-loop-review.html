阶段摘要

本阶段关键决策

  • 一条三段冒险内部挂载 command_runner、hand_follow_dodge、cloud_stack 三个独立运行时，分别处理离散高跳、连续跟手和拳掌叠云
  • L1/L2/L3 时长固定 40/45/50 秒，每关 6 枚收集物；到达终点即解锁下一关，不按成绩锁关
  • L1 高跳峰值 clamp(150px,24vh,220px)，L2 在 None/Unknown 时仍跟随掌心 Y，L3 每轮拳掌只加一朵云；所有碰撞或不足都软恢复

被放弃的方案

  • 不继续三个同构跑酷关，不用一个按目标动作分支伪装成三种运行时
  • 不引入额外必需手型，也不复刻经典 Flappy 的重力窄缝即死
  • 不使用生命值、Game Over、掉落收集物、失败评级或完成成绩门槛

进入下一阶段的条件

  • 已满足：04A 用 ModeDefinition.runtimeType 定义三运行时和 LV-00–LV-03 宿主
  • 已满足：集成 04B 实现 L1 高跳、L2 Unknown 跟手、L3 叠云/补垫/星星与五视口单屏
  • 后续由真实儿童试玩校准 L1 手感、L2 理解速度和 L3 动作疲劳

不需要 PM 审查的执行细节

  • L2 EMA 0.28、3.5% 死区、单帧最大 12% 位移与 600ms grace
  • 目标毫秒值、CSS 云层高度、测试注入 API 和动画粒子

Q-03-CORE-001 Route hint: L2

是否确认 L1/L2/L3 分别使用 command_runner、hand_follow_dodge、cloud_stack 三个独立运行时，而不是同一跑酷状态机换参数？
