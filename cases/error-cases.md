# Error Case Library

本文件记录本项目工作流执行中的真实错误、返工和质量问题。它是事实库，不是规则库。

## 何时必须记录

出现以下情况之一时，先记录 case，再决定是否需要抽象规则：

- 用户明确指出产物方向、范围、页面形态或字段模型错误。
- 阶段门禁被跳过、上游信息被误读、产物写错目录或命名错误。
- 原型规格校验、HTML 静态检查、浏览器检查或人工 QA 发现质量问题。
- 同一类问题在不同阶段、页面或模块里重复出现。
- AI 基于未经确认的假设写出了会影响决策的结论。

## 使用原则

- 只记录已经发生的事实，不把推测当事实。
- 单个错误不能直接升级成通用规则。
- 能修复当前项目的问题，不代表它能进入通用 workflow。
- 如果只能说明本项目业务特殊性，留在本文件，不写入 `rules/rule-candidates.md`。
- 如果可能抽象成规则，先写入 `rules/rule-candidates.md`，不要直接改 `rules/active-rules.md`。

## CASE-018：摄像头准备页按钮被裁切且主要操作图标未统一为生成式画风

- 日期：2026-08-15
- 发生阶段：Phase 4B 集成式可试玩 MVP
- 相关产物：`04B-prototype-手势小狗探险MVP.html`、`assets/ui/control-icons/`、`assets/ui/panels/`
- 触发方式：用户在最新试玩中以三张截图指出。
- 期望行为：摄像头准备页的拍摄按钮应完整显示并保留透明安全边距；继续、改用按键、返回家长设置、右上家长控制以及游戏内主要手势/动作图标应统一使用同一套手绘木质徽章画风。
- 实际错误：GI-02 继续使用横向相机按钮切片，右边缘贴近图片边界而出现错误裁剪；相邻三个操作仍是普通 CSS 文字按钮；右上家长入口、准备/运行/暂停中的爪印或线框 SVG 也未完成视觉资产传播。
- 证据：用户提供的 `codex-clipboard-ce17a428-513d-4ffe-9fe5-41c50f8661cc.png`、`codex-clipboard-f38f0bc0-e36d-44c7-9c82-3e70210f7af9.png`、`codex-clipboard-e5cfeb18-ca47-447e-8445-903ef1d9b56d.png`；修复前 GI-02 引用旧横向 `wide/button-4.png`，多处主要控制仍含大尺寸内联 SVG。

- 影响说明：不阻断流程，但同一页面内出现位图裁切和两套图标语言，明显削弱游戏化一致性与按钮可辨识度。
- 根因分类：QA 未覆盖（只验证图片加载和最小点击面积，未验证透明边缘安全区，也未对主要游戏流程做图标资产传播盘点）。

- 修复状态：fixed

## CASE-004：隐藏页面滚动后部分 screen 内容仍可能超出视口

- 日期：2026-08-12
- 发生阶段：Phase 4B 集成式可试玩 MVP
- 相关产物：两份 `04A-prototype-spec-*.md`、`04B-prototype-手势小狗探险MVP.html`、`tests/phase4b-mvp-targeted.mjs`
- 触发方式：用户明确要求页面仅单屏自适应、不可上下滑动；新增全 screen 浏览器检查后复现 GI-02 内部高度超过视口。
- 期望行为：GI-01–GI-06、LV-01–LV-03 与展开的家长抽屉在 1440×900、1024×700 内完整呈现，不依赖页面或抽屉纵向滚动。
- 实际错误：原规则只检查横向溢出；初步设置 `overflow:hidden` 后，GI-02 内部内容高度仍超过视口，存在被静默裁切的风险。
- 证据：专项浏览器检查首次报告 GI-02 `scrollHeight=979`、`clientHeight=900`；修复后两个 viewport 的 9 screen + 抽屉检查全部 PASS。
- 影响等级：P1
- 影响说明：可能让底部状态或操作不可见，5 岁儿童与家长无法通过滚动发现被裁内容。
- 根因分类：QA 未覆盖
- 修复方式：在两份 04A 增加单视口验收；04B 固定产品画布和 screen 高度、收紧低高布局、为关键 grid 使用 `minmax(0,1fr)`；测试同时断言根页面、内容 surface 和可见控件都在视口内。
- 修复状态：fixed
- 是否可能抽象成规则：否
- 如果否，为什么只能留在本项目：单屏无滚动是用户针对本游戏明确确认的产品约束，已作为 AR-002 生效；不适用于需要长内容阅读的一般 Web 页面。

## CASE-006：统一阈值让自然张掌比握拳更难进入稳定结果

- 日期：2026-08-12
- 发生阶段：Phase 4B 本地手势识别
- 相关产物：`gesture-recognizer-runtime.mjs`、`tests/gesture-runtime-targeted.mjs`
- 触发方式：用户实测反馈只能识别握拳，张开手掌无法识别；代码审查确认所有手势共用 0.65 分数阈值和 4/5 稳定窗口。
- 期望行为：儿童自然张开手掌时，即使 canned classifier 分数略低，也能利用已检测的 21 点手部关键点形成可靠 `Open_Palm`；低置信噪声仍被拒绝。
- 实际错误：模型分类器在 0.65 前置过滤后把低分张掌直接变成 `None`，前端只画关键点却不利用关键点判断手指伸展；握拳通常轮廓更紧凑，因此在同一阈值下更容易稳定。
- 证据：旧运行时 `scoreThreshold=0.65`、统一 `stableWindowMatches=4`；新 targeted test 覆盖低分 Open_Palm、关键点兜底、Closed_Fist 和低置信噪声拒绝。
- 影响等级：P0
- 影响说明：首个动作即无法通过，真实摄像头主路径形成死路。
- 根因分类：其他（手势间分数分布差异未做校准）
- 修复方式：分类器入口阈值降至 0.35 以保留候选；运行时使用按手势阈值（张掌 0.45、握拳 0.55、点赞 0.50）与稳定窗口（3/5、4/5、3/5）；当模型没有可用类别但至少三根手指关键点呈伸展时，本机兜底为 Open_Palm。
- 修复状态：fixed
- 是否可能抽象成规则：否
- 如果否，为什么只能留在本项目：阈值和关键点启发式需要结合本项目动作集与真实儿童试玩继续校准，不能直接推广到所有手势产品。

## CASE-007：动作测试的倒计时与释放门让识别结果没有形成可理解的角色响应

- 日期：2026-08-12
- 发生阶段：Phase 4B 集成式可试玩 MVP
- 相关产物：两份 `03-feature`、两份 `04A-prototype-spec`、`04B-prototype-手势小狗探险MVP.html`、`gesture-recognizer-runtime.mjs`
- 触发方式：用户真实试玩并提供截图反馈。
- 期望行为：5 岁儿童只需理解一个短动作循环，系统实时告诉孩子当前看到的手形；有效动作立刻驱动角色，动作后短暂冻结，并通过一个明确复位手形重新解锁。
- 实际错误：练习先等待入镜、再进行 3、2、1、再开启 4 秒观察窗口；张掌即使被识别，也可能发生在观察窗口外而不触发角色。成功后又要求 `None` 释放，但界面没有清楚解释，孩子无法建立“我做了什么—角色为什么动/没动”的因果。

- 证据：用户明确反馈“如果是 Doodle Jump 不应该不断往上跳吗，然后画面会自动向上推移；不要自创玩法”。代码中的 `spawnNextTarget()`、`updateAutoBounce()` 与 `updateLevel()` 也证实世界由单目标时间线驱动。
- 影响等级：P1
- 影响说明：玩家无法形成“越跳越高”的空间目标，也不能从角色与平台的相对运动预测落点；成熟玩法参考只停留在命名层，违背用户已确认的“不自创主循环”。
- 根因分类：核心假设错误 + 竞品机制误读 + 字段模型遗漏 + QA 未覆盖
- 修复方式：进行中；按 L4→L0 重推，新增 playerWorldY/verticalVelocity/cameraY/platforms 等源真相字段，并补相机阈值、世界滚动、下降落台和持续生成平台的浏览器专项。
- 修复状态：open
