# Error Case Library

本文件记录本项目工作流执行中的真实错误、返工和质量问题。它是事实库，不是规则库。

## 何时必须记录

出现以下情况之一时，先记录 case，再决定是否需要抽象规则：

- 用户明确指出产物方向、范围、页面形态或字段模型错误。
- 阶段门禁被跳过、上游信息被误读、产物写错目录或命名错误。
- 原型规格校验、HTML 静态检查、浏览器检查或人工 QA 发现质量问题。
- 同一类问题在不同阶段、页面或模块里重复出现。
- AI 基于未经确认的假设写出了会影响决策的结论。

## 使用原则

- 只记录已经发生的事实，不把推测当事实。
- 单个错误不能直接升级成通用规则。
- 能修复当前项目的问题，不代表它能进入通用 workflow。
- 如果只能说明本项目业务特殊性，留在本文件，不写入 `rules/rule-candidates.md`。
- 如果可能抽象成规则，先写入 `rules/rule-candidates.md`，不要直接改 `rules/active-rules.md`。

## CASE-024：L1 视觉落点、中心点判定与恒定跳跃轨迹不一致

- 日期：2026-08-15
- 发生阶段：Phase 3–4B L1 溪边跳跳世界物理。
- 相关产物：`03-feature-核心关卡循环.md`、`04A-prototype-spec-核心关卡循环.md`、`04B-prototype-手势小狗探险MVP.html`、玩法循环定向测试。
- 触发方式：用户真实试玩后明确指出三项问题。
- 期望行为：角色脚底和障碍底边落在立体地面的纵深带内；只有可见主体真实发生空间接触时才判碰，高速帧不能漏判；地面加速后跳跃仍保持可预测的反应与越障窗口。
- 实际错误：角色/障碍分别使用不一致的 CSS `bottom`，视觉上悬浮；目标中心越过固定角色 X 时只抽样一次 `jumpY`，没有主体 hitbox 与 swept interval，导致提前/漏判；跳跃时长/峰值恒定，地面最高加速 1.6× 后横向运动与空中轨迹缺少显式耦合。
- 证据：用户本轮反馈；实现中 L1 判定条件为 `target.worldX<=playerX` 后调用 `resolveCommandTarget()`，只比较单帧 `jumpY` 与 54/72/96px 阈值；角色、箱/原木/坑洞分别使用 `bottom:9%/15%/8.7%`。
- 影响等级：P1。
- 影响说明：孩子看到的接触与扣心不一致，并会在提速后难以建立稳定的起跳节奏，直接损害核心玩法可信度。
- 根因分类：功能规则不完整 + 碰撞模型过度简化 + QA 未覆盖高速跨帧与视觉接触带。
- 修复方式：已按 L2→L1→L0 同步地面接触带、速度耦合弹道、人工内缩 hitbox 与 previous/current swept interval；新增三视口地面/碰撞和 1.0×–1.6× 跳跃物理浏览器专项，4/4 PASS，并回归键盘/出生三视口与 scored loop 9/9。
- 修复状态：fixed。
- 是否可能抽象成规则：否。
- 如果否，为什么只能留在本项目：具体地面纵深、碰撞体与速度曲线属于当前儿童横版玩法的产品参数，需要本项目试玩校准。

## CASE-006：统一阈值让自然张掌比握拳更难进入稳定结果
